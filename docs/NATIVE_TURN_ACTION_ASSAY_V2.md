# Native TURN randomized-hold action assay V2

This is a prospectively frozen, factual development replication of the narrow
V1 result that assigned BWE-relative bitrate caps moved encoded payload while
the delivery endpoint remained unresolved. It asks whether that proximal
assignment response is reproducible across a broader set of local capacity
trajectories and procedural source settings. The capture protocol, analysis
code, runtime hashes, action seeds, panel order and primary contrasts are
committed before V2 data collection.

## Scope and design

The panel crosses eight new procedural scene seeds (201--208), four authored
capacity-trace shapes, and two repetitions, for 64 peers and 384 acknowledged
holds. Each peer runs one six-phase, 18-second trace with a 3-second phase
duration:

| Trace | Bottleneck capacity by phase (Mbps) |
|---|---|
| Ramp up | 0.40, 0.55, 0.70, 0.90, 1.15, 1.40 |
| Ramp down | 1.40, 1.15, 0.90, 0.70, 0.55, 0.40 |
| Alternating | 1.30, 0.50, 1.30, 0.50, 1.30, 0.50 |
| Repeated dip | 1.20, 0.35, 1.20, 0.35, 1.20, 1.20 |

At each of six acknowledged holds, the existing native instrument assigns
0.65, 0.85 or 1.05 times the sender-observed BWE through its frozen
SHA-256 pseudo-randomization, with nominal probability 1/3 per arm. It is a
diagnostic action schedule, not a candidate controller. Trial order is frozen
by a separate permutation seed. Every
trace-by-phase cell has at least two assigned holds per action. Assignments
that clip or alias remain in the intention-to-treat analysis and are counted;
they are never removed to improve apparent support.

The two fixed proximal outcomes are the existing pass-through pre-RTP encoded
payload rate divided by assignment BWE in the 1.8--2.6-second hold window
(equal weight per hold), and the request-weighted share of source capture
requests read back within the existing 150 ms request-to-pixel-readback
criterion. Missing and late readbacks count as not on time. The proximal
estimand averages the current assignment over factual histories generated by
the earlier predeclared pseudo-randomized assignments; it does not estimate a
complete controller or a state-conditional action value.

The estimator is peer and within-peer phase fixed effects, a peer-clustered
CR1 sandwich with a t reference on 63 degrees of freedom, equal-hold weighting
for payload and eligible-request weighting for the on-time share. All three
pairwise action contrasts on both outcomes form one six-test Holm family at
0.05. All 384 assigned rows must have both endpoints defined and complete for
the registered contrast family to be reported. If a hold or peer fails, the
partial factual evidence remains sealed and the paired efficacy analysis is
marked unqualified; there is no replacement run, post-hoc exclusion or
per-protocol rescue. No action, confidence, safety or promotion threshold is
changed by this diagnostic.

## Evidence boundary

This varies authored bottleneck capacity and procedural content on the same
single-host Chromium, TURN/TCP and userspace queue. Propagation remains fixed
at 25 ms and the queue mechanism remains the one already used by the V1 probe.
The traces are new settings, not unseen physical network families. The panel
does not validate UDP, the archived/licensed-video pilots, real network
conditions, human QoE, a learned bitrate controller, calibration, safety, or
advantage over tuned whole-session baselines. No simulator labels or
counterfactual outcomes enter capture or analysis.

The raw capture is written only to the external
`~/.cache/networkrlcd/working/native-turn-action-assay-v2/` directory. Its
compact report contains a complete relative-path inventory with byte counts
and SHA-256 hashes. Raw files are never placed in Git, rewritten after sealing
or treated as backed up before a private archive receipt and fresh restore
exist. Existing V1 raw evidence and its frozen recipe are not modified.

## Reproduction

Use the exact committed specification and a fresh raw/report/audit/analysis
path. The capture runner checks all registered source hashes, Coturn and its
shared-library hashes, Chromium and Node versions, the trial crossing,
randomized action support, and the external raw-output location before it
starts. A failed peer leaves its partial raw directory intact and stops the
panel.

    uv run --frozen python -m media_rl.native_turn_probe_v2 \
      --spec configs/native_turn_probe_v2_action_assay.json \
      --raw-out /home/agent/.cache/networkrlcd/working/native-turn-action-assay-v2 \
      --report-out reports/native-turn-action-assay-v2

Then replay every peer and the complete userspace wire ledger before analyzing
the randomized assignments:

    uv run --frozen python -m media_rl.native_turn_audit \
      --capture /home/agent/.cache/networkrlcd/working/native-turn-action-assay-v2 \
      --compact reports/native-turn-action-assay-v2 \
      --out reports/native-turn-action-assay-v2/independent-audit.json

    uv run --frozen python -m media_rl.native_turn_action_panel_v2 \
      --spec configs/native_turn_probe_v2_action_assay.json \
      --capture /home/agent/.cache/networkrlcd/working/native-turn-action-assay-v2 \
      --compact reports/native-turn-action-assay-v2 \
      --inventory reports/native-turn-action-assay-v2/local-evidence-inventory.json \
      --audit reports/native-turn-action-assay-v2/independent-audit.json \
      --out reports/native-turn-action-assay-v2-analysis

The compact report and analysis are not archive verification. No raw bytes may
be pruned or represented as backed up until the pinned private archive
workflow verifies every remote and fresh-download hash.
