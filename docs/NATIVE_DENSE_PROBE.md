# Dense scalar-control mechanism probe

## Status and evidence boundary

V5 is rejected before repeatability or performance validation. All eight selected-controller peers pass independent full raw replay with no ten-millisecond tail failure, but only **2/680 decisions (0.29%)** execute genuine neural departures from both old BWE and GCC; only six attributed source requests follow those decisions. Probability/support recalibration preserves the actor, risk heads, train-only normalization, learner/config and source provenance. Only 300 kb/s has enough selected factual support; its cross-fitted worst-group residual plus slack gives a **0.102094 margin**, already larger than the unchanged 0.1 miss budget. Other margins are 1. Thus *every possible input* is risk-vetoed after recalibration, not just this recorded rollout. `results/jobs/native-repair5-selected-diagnosis.json` verifies all 255 retained selected/calibrated hashes and three canonical artifacts. There is no learned-policy gain or promotion.

The eligible V5 critic scores on these actual runs lie in [5.09,13.47] with maximum ensemble spread 1.71; the much larger global extrapolation spread reported earlier is not the eligible-state spread. Convergence remains unproven. The main demonstrated control bottleneck is now sharper: **673/680 BWE-valid steps (98.97%) have no higher seven-grid cap inside 95% of current BWE**, while **655/680** still have >=25% continuous headroom over the old quantized BWE cap. This is descriptive state-dependent evidence, not a counterfactual throughput certificate. It motivates a mechanism test instead of weakening risk/BWE limits or spending validation on an inert checkpoint.

## Independent diagnostic implementation

- `src/media_rl/native_dense_control.py` and `benchmarks/native_rtc/dense_control.mjs` implement legacy quantized 85%-BWE, **continuous 85%-BWE**, fixed450 and native-GCC-ceiling controls. Continuous control floors the integer result and retains the physical [150,000,4,000,000] scalar domain. Missing BWE retains legacy minimum-cap behavior. Minimum-cap saturation is a physical-domain exception, not neural safety qualification.
- `dense_actuation.mjs` declares a new **scalar** ABI, never the old 14-action ABI. It permits only integer encoder maxBitrate and native zero jitter target, verifies actual native getters/setters, keeps maxFramerate 30, restores the receiver target if setting encoder parameters fails, and does not actuate FEC/codec/pacing.
- Raw sender features keep the **actual scalar cap**. Only the non-actuated, no-model legacy repair shadow receives an explicitly recorded floor-cap projection needed by its old seven-cap ABI. Projection does not mutate raw observations, pretend to be a new action-conditioned model or earn neural credit.
- `native_dense_study.py` and `dense_episode.mjs` preserve the verified movie inode/range loader, owned pre-marker RGB, pixel-ID/PSNR/deadline labels, transported causal ACKs, source/readback association, full wire-ledger replay, source/hash/runtime locking and native maintain-framerate reflection. Controller-choice computation is included in total inference timing.
- The new protocol allows **diagnostic only**, no trained dense model, no learner, no train/calibrate/promote command and no resume/recollection. Failed/partial prefixes stay in their original output directory. Full independent raw replay follows collection. All V5 and older modules/labels/weights remain unchanged.

**Checks:** 18 targeted Python tests, eight Node tests and 15 original-command dispatch regressions pass; bounded Ruff/JS syntax checks pass. A separate extracted wheel verifies Python/JS scalar/shadow parity, transitive assets, all three commands and installed prospective planning. It confirms all **36 V5 / 33 V4 engine bindings**, 255 selected/calibrated hashes and three canonical artifacts unchanged. See `results/jobs/native-dense-package-proof.json` (its engine fields count extra bindings separately from the 19 shared base bindings). These are software/package proofs, not native efficacy.

## Completed native diagnostic

`configs/native_dense_probe_v1.json`: seed **6101**, untouched Tears of Steel **[660,680) s**, one prospectively declared stable source/schedule group, **eight peers** (four controls, two repetitions), three six-second phases. Controls are `bwe`, `bwe-continuous`, `fixed450`, `gcc`; the same original shadow inference is run for every control. The fixed control is exploration, not a claim that the risk gate would accept 450 kb/s. The source is synthetic loopback, not representative real-world transport.

All eight peers complete and pass independent full read-only raw replay; no ten-millisecond inference-tail failure occurs. Mean on-time delivery is 56.01% legacy BWE, 58.87% continuous85, 75.35% fixed450 and 51.02% GCC. These are descriptive results from one group, not confidence-qualified gains. `results/jobs/native-dense-mechanism-diagnosis.json` attributes two distinct problems: low-cap startup largely loses unobserved source frames; higher adaptive rates can accumulate native playout delay and late frames even when they satisfy current BWE. Fixed450 is inside 95%-BWE for about 98.35% of attributable first-phase requests and all later requests on its own trajectory; that is not counterfactual safety certification. Native-GCC repetition results range from 79.85% to 22.18% on-time, underscoring the lack of repeatability. Cold-start misses remain in all metrics and future labels; they are not hidden by dropping early phases. All 57 parent and 232 child artifact hashes remain unchanged.

Repeated peers are **one independent group**; any difference is descriptive and cannot qualify a learned policy.
