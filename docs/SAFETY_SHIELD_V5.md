# V5 action-wise safety screen

**Status:** protocol frozen before and completed on the official v5 validation/test panels. Validation promoted the action-screen candidate; both stages passed artifact audit (274 validation, 307 test artifacts). The source model is the audited v1 checkpoint set in `results/paper-v1/`; policy, safety ensemble, calibrator and fallback are not retrained. This is a controller-level action-selection ablation, not a new learned policy.

## Motivation and exact intervention

Chen et al.'s Adaptive Chance-Constraint Safeguards (ACS) evaluates proposed actions against a chance constraint and projects into a safe action set, but their method also learns a recovery policy and establishes results under a formal model and assumptions. V5 is not an ACS implementation and has no safety theorem. It tests only whether a small action-level filter can improve the empirically measured QoE/risk tradeoff of RLCD's existing one-step predictor.

For each valid observation, v5 ranks the v1 policy's 42 joint bitrate/FEC/mode actions by Q value and examines the top five (`GateConfig.shield_top_k=5`). In rank order, it accepts the first action whose existing ID-calibrated next-interval safety probability is at least 0.90 and whose state telemetry support score is no greater than the frozen model support limit. If none of the five pass, telemetry is invalid/stale, or support is rejected, it invokes the same deterministic safe fallback as v1. It does not change the confidence calibrator, threshold, policy weights, risk labels, predictor or baseline controller. The unshielded greedy proposal, actual action, proposal confidence, chosen-action confidence, reason and realized next-step safety outcome are separately retained in the step log.

This is a one-step empirical screen only. The ID calibrator was not fitted for every counterfactual action, top-five selection can induce selection bias, and a next-step pass does not compose into episode safety. The support check is a heuristic telemetry-distance test. No formal shielding, invariant-set, deployment-safety, or unseen-mechanism claim is made.

## Frozen panel and decision rule

`configs/safety_shield_v5.json` fixes ten v1 model seeds, ten validation trace seeds (6701–6710), ten disjoint final trace seeds (7701–7710), top-five screening, the 0.90 threshold, and the selection limits. The earlier one-trace controller smoke probe (bufferbloat, seed 6601) is excluded from both official panels. Each panel uses the same eleven synthetic scenarios; all scenario mechanisms are known, so the result is fresh-realization evidence, not unseen-mechanism generalization.

Validation compares `shielded` to the exact matched `calibrated_v1` controller on paired traces. Promote only if every condition holds: ID QoE loss ≤0.03; ID violation increase ≤0.01; aggregate stress violation increase ≤0.02; every named stress-family violation increase ≤0.03; and gain >0.005 in

`0.5 * (mean_ID_QoE + mean_stress_QoE) - 5 * mean_stress_violation_rate`.

Otherwise the reference remains v1. The selection JSON and validation-manifest hash are persisted before the 7701–7710 test is created. The fresh test evaluates the shield candidate regardless of the locked selection for diagnostic reporting; test results never revise promotion. Confidence intervals condition on the fixed trace panel and resample model seeds.

Use a new output directory after any implementation/protocol change; partial stages are not resumed. Research motivation and source/retrieval details are recorded in `research/RELATED_WORK.md` and `research/references.bib`.

## Official v5 outcome

Validation selected `shielded` before opening the final traces. ID QoE was 2.0585 for v1 versus 2.0913 for the screen, and ID violation rate was 0.5246% versus 0.4567%. Stress QoE was 1.0812 versus 1.0984; aggregate stress violation rate was 10.2510% versus 10.2343%. The fixed selection score increased from 1.05730 to 1.08312 (+0.02582), passing all predeclared bounds. These figures are recorded in `selection.json`, bound to the validation manifest hash.

The disjoint test contains 8,800 episodes (10 model seeds × 10 held-out trace seeds × 11 scenarios × 8 controllers). Relative to matched `calibrated_v1`, the screen's ID QoE gain was +0.0259 (95% model-seed interval [+0.0135,+0.0387]) and violation-rate change was −0.00144 (−0.144 percentage points; interval [−0.219,−0.074] pp). Its ID p95 virtual latency was 1.18 ms lower and fallback rate 3.05 percentage points lower. On OOD traces, QoE change was +0.0136 (interval [−0.0018,+0.0298]) and violation change +0.00004 (95% interval [−0.00403,+0.00354] as fractions, or [−0.403,+0.354] pp), neither establishing a gain; OOD p95 virtual latency and fallback were lower. At ID/OOD, the screen replaced only 0.335%/0.438% of decisions on average. Among changed-action steps, same-state observed violation rates were 23.55%→11.46% (ID) and 60.69%→26.35% (OOD); these counterfactual-conditioned diagnostics are descriptive, not causal long-horizon estimates.

### Post-lock selected-action calibration audit

After the final test and promotion decision were locked, we streamed `steps.csv.gz` to pair each logged `action_confidence` with the one-step safety label of the action actually executed. This post-hoc diagnostic did not retune the screen. On OOD/stress rows with an accepted action score, mean confidence was 99.84% versus 94.23% mean observed safety (a 5.61 pp overstatement; 95% source-model-seed interval [5.09, 6.10]). Among the 1,841 changed-action steps, confidence was 95.48% versus 73.65% observed safety, a 21.83 pp overstatement [8.22, 39.78]. The selected alternatives reduce same-state one-step unsafe frequency from 60.69% for proposals to 26.35% for replacements, but are still overconfident under stress. The 803 ID replacements show wide uncertainty. Table `paper/generated-shield/table_action_selection_calibration.tex` reports source-model-seed intervals; its provenance records the exact `steps.csv.gz` hash. Counts are serially dependent time steps, not independent samples, and these conditional outcomes are neither long-run causal effects nor safety guarantees.

The fresh test therefore supports a modest improvement over the matched calibrated gate on this fixed synthetic ID panel, not a general controller win: heuristic and GCC-like baselines retain better ID QoE/safety tradeoffs, and the screen does not significantly improve OOD violation rate. Screening is subject to action-selection calibration bias and carries no formal safety guarantee. All intervals condition on the trace panel and resample ten source-model seeds.
